# Нишпорка

**Нишпорка — занотуй свою пригоду.** Простий вебзастосунок для планування подорожей:
створюєш подорож (назва, місце, дати) і збираєш у ній справи, речі в дорогу,
бюджет і посилання на місця.

Сайт: https://khrystynapm.github.io/nishporka/

Це перша версія (V1), зроблена як навчальний проєкт PM-а: від вимог і макета до робочого сайту.

## Що вміє

- **Список подорожей** — картки всіх подорожей з бази (на ноутбуці сіткою, на телефоні списком).
- **Подорож:** створити, відредагувати, видалити (з підтвердженням у діалозі).
- **Екран подорожі** (адреса `…/#trip/номер`, наприклад `#trip/1`) з 4 блоками:
  - **Справи** — з галочкою «зроблено»;
  - **Речі в дорогу** — з галочкою «спаковано»;
  - **Бюджет** — витрати в євро і «Разом … €» під списком;
  - **Місця** — назва й необовʼязкове посилання (відкривається в новій вкладці).
- У кожному блоці: додати, редагувати, видалити рядок, згорнути блок; лічильники в заголовках
  («2 з 5» для справ і речей, кількість для місць).
- Працює на телефоні, планшеті й ноутбуці.

## Як це працює

```
Браузер (index.html + app.js + nishporka.css)
        │  запити через інтернет (fetch, REST API)
        ▼
База Supabase (Postgres): trips + 4 таблиці блоків
```

- Сторінка — звичайні файли HTML, CSS і JavaScript, **без фреймворків і без збірки**.
- Дані зберігаються не в браузері, а в базі **Supabase**, тому те саме видно з будь-якого пристрою.
- `app.js` звертається до бази через одну спільну функцію `api()` (читати / додати / змінити / видалити).
- Сайт публікує **GitHub Pages** з гілки `main` (корінь репозиторію): злили зміни в `main` —
  за хвилину-дві сайт оновився.

## Файли

| Файл | Що в ньому |
|---|---|
| `index.html` | Сторінка: каркас усіх екранів (список, подорож, форма, діалог видалення). |
| `nishporka.css` | Стиль з макета V1: кольори, шрифти, розміри, адаптивність. |
| `app.js` | Уся логіка: вигляд «телефон / ноутбук», список, форма, екран подорожі, блоки, суми й лічильники, діалог видалення. Опис 4 блоків — в обʼєкті `BLOCKS`. |
| `config.js` | Адреса бази Supabase і publishable key. |

## База даних (Supabase)

| Таблиця | Поля (крім `id` і `created_at`) |
|---|---|
| `trips` — подорожі | `title`, `location`, `start_date`, `end_date` |
| `todos` — справи | `trip_id`, `text`, `done` |
| `packing_items` — речі | `trip_id`, `text`, `packed` |
| `budget_items` — бюджет | `trip_id`, `title`, `amount_eur` |
| `places` — місця | `trip_id`, `title`, `url` |

`trip_id` вказує, до якої подорожі належить рядок. Якщо видалити подорож, база сама
видаляє всі її справи, речі, витрати й місця (`on delete cascade`).

## Безпека і обмеження V1

- **Ключ у `config.js` публічний** (publishable key) — так і має бути, його бачить кожен, хто
  відкриє сайт. Він дає лише ті права, які дозволяють правила бази (RLS).
  **Secret key (`sb_secret_…`) чи пароль бази сюди класти не можна ніколи.**
- **Доступ відкритий:** у V1 немає входу, тож будь-хто з посиланням може переглядати,
  змінювати й видаляти дані. Це свідоме рішення для V1; у базі для цього одне правило
  `v1_open_access` у кожній таблиці — у V2 його замінять правилами з входом.
- **Пауза Supabase:** безкоштовний проєкт засинає приблизно після 7 днів без активності.
  Тоді сайт покаже помилку. Що робити: увійти на supabase.com і натиснути
  кнопку відновлення проєкту (Restore) — дані не губляться.

## Як подивитися локально

Відкрити `index.html` у браузері (подвійний клік) — нічого встановлювати не треба.
Сторінка працює зі справжньою базою, тож усі зміни видно й на сайті.
